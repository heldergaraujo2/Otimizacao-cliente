# DECISIONS — technical decision record

Format: **D<n> — title**. Context, alternatives, decision, consequence, open questions.
Routine and reversible decisions are recorded here instead of asking for confirmation.

## D1 — Single central monorepo with npm workspaces (TypeScript)

**Context:** the project needs a client, a server, shared protocol/resource code and tools; the
master command forbids creating many repositories without technical need.
**Alternatives:** separate repositories per component; C#/.NET (matching the reference clients).
**Decision:** one repository, npm workspaces (`packages/*`, `tools/*`), TypeScript (ESM, strict) on
Node ≥ 22.
**Why:** the runtime is the only complete toolchain available in the execution environment (Node,
npm, python3); TypeScript gives one language for server, tools, tests and the client's browser code.
**Consequence:** the reference C# sources are read-only references; protocol/format behaviour must be
ported and proven by our own tests. Open question: whether the final client should be re-hosted on a
native runtime for GPU-bound scenes — measured later (Fase 12) before deciding.

## D2 — OpenMU is the protocol source of truth, reimplemented from scratch

**Context:** we must not copy code from `xulek/muonline` (no licence), and OpenMU is MIT.
**Decision:** our `mu-protocol` is an independent implementation whose behaviour is *proven* by
replaying vectors generated from OpenMU (`tests/vectors/openmu_simplemodulus.json`, pinned commit in
`third_party/PINS.json`) and by matching documented packet offsets.
**Consequence:** any divergence shows up as a failing test rather than silent incompatibility.

## D3 — No proprietary data in Git; fixtures generated by our own builders

**Context:** game assets (BMD/OZ*/ATT/MAP/OBJ, `.pak` contents) belong to Webzen; MIT/ISC cover code,
not data.
**Decision:** the repository ships **no** game data. Tests use ``packages/mu-formats/src/testing/fixtures.ts``,
which implements the *container/writing* side of each format. Real assets are read at runtime from a
user-provided directory (`MU_REENGINEER_DATA`), never copied into the repository.
**Consequence:** format readers are validated structurally (round-trip, offset-exact) in this
environment; conformance against real assets is a documented, user-runnable step
(`docs/ASSET_PIPELINE.md` §Validation).

## D4 — Level 3/4 network evidence is produced with real sockets, not mocks

**Context:** the master command requires integration evidence, but a browser/GPU is unavailable here.
**Decision:** the server and the client's game logic are implemented as Node processes/libraries;
integration tests open real TCP sockets (two processes, real framing/cipher/state machine). The
browser renderer consumes the same logic, so only rendering (Levels 5–7) is marked
`PENDENTE DE VALIDAÇÃO HUMANA`.
**Consequence:** connection, authentication, movement and disconnection are genuinely testable here.

## D5 — Dependency-free PNG encoder, JPEG delegated to the host

**Context:** exporting decoded OZ* textures needs an image encoder; adding native image libraries
(`sharp`) pulls binaries and build complexity.
**Decision:** `packages/mu-formats/src/png.ts` writes PNG using `node:zlib` only. OZJ keeps its
embedded JPEG and exposes the offset, letting the browser (or any host decoder) handle it.
**Consequence:** exports work offline and reproducibly; no native dependencies. PNG encoding is the
slowest benchmarked path (~28 images/s at 512×512) — see `docs/PERFORMANCE.md`.

## D6 — Unsupported ciphers fail loudly

**Context:** ModulusCryptor supports 8 algorithms; TEA and RC5 are implemented.
**Decision:** declaring the algorithm id mapping and throwing `UnsupportedCipherError` with the
algorithm name for the rest, instead of guessing or silently returning garbage.
**Consequence:** real files using CAST5/ThreeWay/RC6/MARS/IDEA/GOST are reported precisely; the
missing cipher is a known gap (`project/CURRENT_STATE.md`, gaps list) rather than a data-corruption
risk.

## D7 — Cipher variants are named after the original protocol wording

**Decision:** keep `'new'`/`'old'` SimpleModulus variants (8→11 and 32→38 byte blocks) and the
XOR3/XOR32/BUX masks named as in the reference implementations, so findings from OpenMU/xulek code
map one-to-one onto our code during debugging.
**Consequence:** slightly unusual naming, much lower risk of mis-translation.

## D8 — `third_party/` is ignored except the pins

**Decision:** clone references outside the repository (or in `third_party/*`, ignored) and commit only
`third_party/PINS.json` + `third_party/README.md`. `.gitignore` ignores `third_party/*` (contents),
never the directory itself, otherwise git cannot re-include the pinned files.
**Consequence:** reproducible research provenance without vendoring third-party code.

## D9 — The client keeps a headless core

**Decision:** game logic (session, character, movement, resource loading) lives in
`packages/mu-client` behind an interface; the WebGL renderer is one consumer. Tests drive the core
directly.
**Consequence:** Level 3/4 automation without a GPU, and a future native/alternative renderer is a
swap, not a rewrite.
